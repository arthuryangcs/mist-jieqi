# 雾里见招 · Mist Jieqi

独立的本地浏览器程序，纯 JavaScript + HTML/CSS，棋盘、规则引擎和搜索代码均在本目录。没有 npm 运行依赖、账号、外部 CDN 或联网分析。未修改其他项目。

## 启动

需要 Python 3；Node.js 20+ 仅用于测试。

```sh
git clone https://github.com/arthuryangcs/mist-jieqi.git
cd mist-jieqi
python3 -m http.server 8765 --bind 127.0.0.1
```

启动后，在运行服务器的同一台电脑上打开 [本地揭棋页面](http://127.0.0.1:8765/)。该地址不是在线演示地址。也可以执行 `npm start`。用 Ctrl+C 停止服务器。直接双击 HTML 的 `file://` 地址不能可靠启动 ES 模块和 Worker，请使用 HTTP 地址。服务器仅绑定本机，无公开发布。

## 使用

- **人机对战**：你执红先行，点击棋子再点击绿色落点；暗子棋面留白，第一步按原始位置角色走。可选择 1/2/6/15 秒思考。悔棋撤回至你上一手前；电脑思考中也可立即悔棋、重开。停止电脑搜索会撤回你的上一手，避免停在黑方无法行动的状态。
- **机器自动对战**：切换到该模式后点击“开始自动对战”，双方电脑按同一思考时长交替落子，直到胜负或和棋。每步之间留出短暂停顿便于观战。可随时暂停并保留棋盘，继续时从当前行棋方恢复；“电脑走一步”只推进一手。自动模式下悔棋只退一步并暂停，重新开局也保持观战模式并暂停。切换到编辑或人机模式会停止自动循环。双方分别使用本方可见信息脱敏与采样搜索。观战可切换红黑视角；切换只影响显示，不会把另一方私人吃子信息传给 AI。
- **分析当前局面**：对战和编辑模式均可使用。正分有利于分析开始时的行棋方，100分约一兵。显示当前搜索推荐前五着、搜索评分、样本标准差、搜索深度、节点数和耗时。将死/困毙胜负分约 ±99000。
- **局面编辑 / 分析**：默认复制当前对局。选择红/黑明子、暗子或擦除，再点棋盘；通过“行棋方”设置轮谁走。暗子只能放在己方原始暗子位置，按位置自动设定首步角色，**不录入暗子真身**。双方均必须有且仅有一枚将帅；不允许非行棋方被将军、将帅照面或棋子数量超额。
- **已知离盘身份**：输入字母，例 `RNP` 为车、马、兵；`R车 N马 B象 A士 C炮 P兵`。未知离盘棋子自动记为被吃暗子，其身份仍在未知池。池的总数包含盘上暗子和离盘暗子，所以不等于盘上暗子数。也可输入剩余未知库存（包含存活暗子和未知被吃暗子），与已知吃子记录同时录入时须一致。只录入当前信息视角已知的身份，包含本方吃到的敌方暗子；修改行棋方不会切换信息视角。界面显示已揭、存活暗子、未知被吃和数量校验。未录入被吃明子会降低分析准确性；无法从任意局面的棋盘单独还原这部分信息。
- “走推荐一步”可以推进明子并自动切换行棋方。推荐暗子时不能凭空知道揭开身份，因此需用编辑器擦除原子、在目标点放置实际揭开的明子，再切换行棋方。当前视角已知的被吃明子及暗俘请补入对应记录。不会把采样身份当成事实。
- 编辑状态切回对战保留原对局；修改后的编辑局面用于辅助分析，不会覆写原对局。页面刷新会清空全部状态。

## 核实规则及本版选择

查阅时间：2026-10-18。

1. [棋者象棋：揭棋玩法规则](https://qizhe.org.cn/home/?p=848)：将帅原位明置；每方15枚同色暗子随机摆；暗子按原位置角色走第一步并揭开；暗子被吃不揭示给原持有者；明士、象可过河。该站另有特定的长捉、长将、循环与步数裁判规则。
2. [《动态规划求解状态总数算法在揭棋上的应用》，刘丰瑞等，智能计算机与应用，2025年第15卷第6期，151–155](https://computing.hit.edu.cn/_upload/article/files/f6/ee/527093f94154810b5480eb7d955b/0641067c-b19d-429f-8559-f2bac072fa90.pdf)：论文1.1–1.2节与上述开局、揭子和士象过河核心规则一致。论文用于核对规则与复杂性，不是赛事裁判规范。
3. [腾讯：揭棋玩法说明](https://image.qqchess.qq.com/test_160324/activity/html/jieqiguize.html)：作为独立玩法来源交叉核对基本规则和暗子吃子可见性。
4. [中华民国象棋文化协会：象棋走法介绍](https://www.cccs.org.tw/Message/MessageView?GroupName=%E7%84%A1%E5%88%86%E9%A1%9E&itemid=57&mid=32&page=0)：用于核对普通象棋的马腿、象眼、九宫和飞将基本走法。

本版采用：红先；明士全盘斜走一格，明象全盘斜走两格且仍塞象眼；暗士限九宫、暗象不过河；将帅限九宫；不能送将、不能将帅照面；将死和困毙均判负。暗子在未揭前的攻击能力按其原位角色判定。**被吃暗子的身份仅吃子方可见，被吃方不可见；被吃明子的身份双方可见。** 人机模式固定红方信息视角，电脑只收到黑方能看到的信息；对手的私人库存和分析不会显示给玩家。

简化和棋：同一公开局面（含行棋方）出现第三次、连续120步未吃子且未揭子、或总400步时判和。**没有实现特定平台的长将、长捉、80闲步和200步裁判**，不能用于正式比赛裁决。

## AI 实现与限制

兵位首着的机制、通用排序消融与当前实际搜索深度见 [OPENING_ANALYSIS_REPORT.md](OPENING_ANALYSIS_REPORT.md)。没有首步走兵规则或兵位奖励：相同先验实验尚未证明兵位首着最优。默认仅按剩余身份的揭后活动期望与原角色机会成本调整访问顺序，不给根搜索分数补分；完整活动度估值因开销保持关闭。

最新优化和当前规则对照见 [ENGINE_STRENGTH_REPORT.md](ENGINE_STRENGTH_REPORT.md)：内部8局2胜5和1负，其中1胜来自旧引擎技术超时；正常7局1胜5和1负。指定 PikaJieQi 对照中，旧版、新版各0胜4负，均无技术负。小样本尚不能证明整体棋力提升。

历史独立宿主计时保护与指定引擎8局重赛见 [TIME_CONTROL_REPORT.md](TIME_CONTROL_REPORT.md)：8局全部正常结束、技术超时0；当时版本0胜8负。旧超时记录保留，没有排除技术负来改善成绩。**该历史对赛采用“双方不看暗俘”变体，不与上述当前规则成绩合并。**

JavaScript + Web Worker。视角快照在工作线程边界删除盘上暗子和本方被吃暗子的真身；身份池减去盘上明子、公开被吃明子，以及本方吃到的敌方暗子。对当前观察者未知的被吃暗子作为离盘潜变量保留在池中，不计为盘上子力。分析缓存与采样种子包含信息视角，避免两方私人信息混用。默认按当前可见信息固定种子、8个平衡无放回样本，迭代加深、PVS/α–β、增量哈希、置换表和吃子/应将搜索；各根候选共用样本。完整分析缓存包含可见盘面、库存、行棋方、裁定历史和思考预算。

全明局面100分约一兵，有暗子时先平均各样本的启发式效用再换算综合分，避免直接混合将杀与子力分。±为有限分尺度的样本标准差，不是置信区间。启发式胜率没有训练或对局校准；样本胜局不等于所有未知布局都获胜。搜索仍有视野和策略融合限制，不保证最优。

默认增加观察者暗俘库存的搜索内更新、库存均值吃子排序、killer排序、每条路径最多2次应将延伸和轻量将帅安全项。更昂贵的活动度估值保留为消融选项，默认关闭。Worker仅传前五候选，减少线程通信；提前返回余量用于控制墙钟，不能保证系统暂停时的硬实时。既有4个双车强制将杀局面在名义2层加应将延伸下通过，不能据此推断专业棋力。

本轮诊断、性能前后数据、实战复盘、官方分支及用户指定PikaJieQi的独立对照见 [OPTIMIZATION_REPORT.md](OPTIMIZATION_REPORT.md)。网页仍是无外部依赖的本地程序，尚未把外部引擎接入网页。本仓库不分发独立对照使用的第三方源码、二进制或权重；来源、固定版本和许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 验证与真实结果

```sh
npm test
node scripts/benchmark.js
```

本机 Node v25.6.0：**82项测试通过，0失败**，包含马腿、象眼、炮架、将军、将帅照面、翻子、暗子被吃、悔棋/重开、编辑器合法性、公开身份隔离、搜索库存恢复、协议隔离、通用揭子排序对称性与同先验、战术回归。

`tests/ui.test.js` 是最小 DOM / Worker 替身下的交互状态测试，覆盖连续重复点击、思考中悔棋/重开、过期结果丢弃、分析结果呈现和编辑非法局面；**不等同于真实浏览器端到端验证**。

战术基准和24步自对弈的原始结果保存在 `benchmark-results.json`。3个小型战术（一步制胜、吃无保护车、拒绝吃兵丢车）全部通过；单层吃子贪心基线只通过其中1个。24步自对弈全为合法着法。此小样本仅验证实现能处理这些战术，不是棋力评级，不能推出对人或成熟引擎胜率。

已补完真实浏览器验证：使用本机官方 Chrome 155.0.8059.80、现有 Playwright Core、独立临时资料目录与保留的 Chrome 沙箱执行，未安装新依赖或修改系统安全设置。16项端到端流程全部通过：首屏90格/30暗子、合法走子揭子与真实 Worker 回应、重复点击、电脑回应后悔棋、思考中悔棋/重开、编辑副本分析、手动摆子与未知池校验、390px移动视口，以及连续机器对战、单步、暂停、思考中悔棋/重开。新增两项使用脚本对手固定合法吃子序列，验证暗俘显示、Worker信息隔离和观战视角；其余流程使用真实Worker。控制台错误、页面异常和HTTP错误均为0。发现并修复了窄屏暗子文字撑高棋子的布局问题，重跑中验证圆形棋子和9:10棋盘。

截图见 [桌面棋盘](browser-evidence/01-desktop.png)、[AI回应](browser-evidence/02-ai-reply.png)、[分析](browser-evidence/03-analysis.png)、[移动视口](browser-evidence/04-mobile.png)、[自动对战](browser-evidence/05-auto-play.png)、[暗俘视角](browser-evidence/07-capture-visibility.png)，完整记录为 [浏览器验证结果](browser-evidence/results.json)。可复跑 `npm run test:browser`：脚本优先使用本项目 `playwright-core`，也可通过 `PLAYWRIGHT_CORE_PATH` 指向已安装模块；可先 `npm install --save-dev playwright-core`，通过 `CHROME_PATH` 设置官方 Chrome 可执行文件路径，通过 `JIEQI_URL` 设置测试地址。浏览器必须可在当前执行权限中启动；本机沙箱权限内启动被终止后，经允许的权限审核启动成功，没有关闭浏览器沙箱。

## 文件

- `index.html` / `style.css` / `board.svg`：中文界面和棋盘。
- `engine.js`：真实状态、公开状态、合法着法和胜负、撤回。
- `ai.js` / `worker.js`：独立搜索与 Worker 接口。
- `editor.js` / `app.js`：编辑校验、交互与搜索生命周期。
- `tests/`：规则、战术和交互状态回归。
- `scripts/benchmark.js` / `benchmark-results.json`：可复现微型基准及一次实测结果。
