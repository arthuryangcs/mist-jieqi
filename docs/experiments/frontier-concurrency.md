# 少根残局并发方案比较与实测

2026-11-05。本轮保留稳定服务和默认引擎，最终 v5 为独立可选实验。固定工作量六个两色难例的耗时几何平均缩短 17.2%，并非所有残局或棋力提升的证明。新独立局面出现快速终局开销退化，12局试赛没有证明棋力改善，仍不默认启用。

## 三种方案及选择依据

| 方案 | 正确性和成本 | 本轮状态 |
|---|---|---|
| 按根解除首批屏障 | 已完成根可立即发后续应手；不拆单根的最重任务。实现较小，仍需保证每根界值有效 | 只做架构分析，没有原型测速。双根难例首批占 98.3%，单根首批占 66.6%，只解除根间屏障不足以解决主瓶颈 |
| 更深分裂、动态领取任务 | 增加可执行任务，但丢失排序、TT 复用和可靠界时会多算。需要线程私有棋盘/历史、可证明的界和取消机制 | 实现有界三层 frontier 和平面动态队列；不是通用递归窃取。实测 v1–v4 失败，v5 恢复首分支等待和 PVS 后通过原固定目标门槛 |
| Pika 式独立搜索 | Pika 的线程各有根状态和搜索，复用共享 TT；重叠工作可增加，占用率高不代表有效工作多。揭棋还必须隔离观察者和暗子世界 | 核对固定源码和既有 CPU 记录，没有把四份互不协作的搜索当成此方案原型，也没有实装或宣称其本机收益 |

固定 Pika 的[线程根状态初始化](https://github.com/brianhliou/pikafish-jieqi-wasm/blob/bcc83f88ee18760e60903d1a3aaa61ef6f70f2c9/src/thread.cpp#L192)、[启动各线程搜索](https://github.com/brianhliou/pikafish-jieqi-wasm/blob/bcc83f88ee18760e60903d1a3aaa61ef6f70f2c9/src/search.cpp#L284)、[全局TT](https://github.com/brianhliou/pikafish-jieqi-wasm/blob/bcc83f88ee18760e60903d1a3aaa61ef6f70f2c9/src/tt.cpp#L31)是架构判断依据，未据此假设其没有重复工作。

原诊断三个残局的任务占用为 1.77、1.94、3.51；原生自身 CPU/墙钟为 1.77、1.93、3.47。v5 分别为任务占用 2.58、2.41、3.69，CPU 2.53、2.39、3.65。任务占用包含锁等待，不能等同执行核数。先前同局面的固定 Pika 自有子进程 CPU 诊断接近 4 核，见[上一轮 CPU 数据](../../benchmarks/search-speed/lazy-history-2026-11-05/cpu-summary.json)；这是历史对照，本轮没有伪称重新做了 Pika CPU 采样。

v5 双根第 10 迭代：首分支阶段约 154 ms，兄弟分支 64 个任务约 578 ms，后续应手约 22 ms。单根第 10 迭代：首分支约 532 ms，兄弟分支约 163 ms，其他应手约 596 ms；仍有一条兄弟子树占约 150 ms。下一轮还有真实的首分支和递归子树尾部可研究，当前并未消除所有串行段。

## 实现与失败版本

v5 以延迟稳定排序版为基线，未混入上一轮使长搜索退化的 lazy-history。仅全明单世界、1–3 个根着进入新调度；暗局八世界调度与覆盖不改，TT访问多一个空代理判断。暗局固定深度节点数相同，微小吞吐波动不当作新收益。每个首应手再展开一层，先搜索一个有序续着建立界，再由最多四线程动态领取其余续着。有限界先做窄窗探测，有改进再验证重搜；所有探测和重搜均计入访问节点和耗时。

棋盘、撤销、历史、杀手着在线程上下文内私有；一个固定父局面的续着共用该父的完整键 TT，probe 在互斥区复制快照，store 也保护。不会跨观察者或暗子样本共享评分界。线程数最多 4，不是 12；额外搜索上下文最多 12。总 TT backing 上限仍为 64 MiB。

| 版本 | 六难例固定目标几何提速比 | 最差提速比 | 结论 |
|---|---:|---:|---|
| v1 私有 TT | 1.111 | 0.854 | 最差未达 0.95，拒绝 |
| v2 续着主变排序 | 1.112 | 0.757 | 仍多算，拒绝 |
| v3 同父完整键共享 TT | 1.106 | 0.899 | 未消除单根退化，拒绝 |
| v4 续着 PVS | 1.098 | 0.738 | 并行启动时多个宽窗分支仍多算，拒绝 |
| v5 先证明主分支再派兄弟 | **1.208** | **0.998** | 达原门槛：几何比 ≥1.10、最差 ≥0.95；还需独立验证 |

这里提速比为基线耗时/候选耗时。v5 六个难例分别为 1.569、1.547、1.133、1.127、0.998、1.004；对应双根耗时减少约 35%–36%，单根约 11%–12%，三根持平。旧测试集用于迭代，不冒充独立留出。

六个原难例诊断中，单根两秒主搜索当前深度从 10 到 11，完成迭代从 9 到 10，选择性最深路径仍为 18 半回合。双根完成迭代仍为 10，最深路径中位仍为 18；三根完成迭代仍为 8，路径中位从 17 到 16。新持续三根局面双方完成 9，最深路径 18。主搜索参数、完成迭代和实际选择性最深路径分开报告，身份概率展开不算一步。Pika 若已确认杀棋仍可能报告 depth 245，不能把它理解为实际走了 245 半回合，其 seldepth 另列于原记录。

## 安全、规则与资源边界

Release、ASan/UBSan、TSan：40 个固定世界搜索、6 个时间预算检查、取消/立即取消/信息隔离、414 个规则观察局面及 11874 次转换、禁 TT 参考均通过。专项 12 例覆盖三个难例两色深度 3/4，逐根分数对本轮基线及独立参考完全一致。新增 512 个并发不同键读写、4000 次同键快照一致性检查。仪表版只用于阶段测量，吞吐结果使用未加任务计时的发布构建。公开构建入口又经过完整189项项目测试、Release三类回归、两色专项及340半回合公开重放，均通过；8项源码散列重建检查通过。真实浏览器未重试，此轮不改页面或默认服务。

对三个固定难例各三次，原生自身子进程峰值 RSS 中位数（MiB）：基线 6.07/9.83/21.75，候选 6.88/10.27/22.89；新增约 0.80/0.44/1.14 MiB。TT 实际分配约 1.76/5.30/5.23 MiB，远非三方都填满相同缓存。RSS 来自自有 `/usr/bin/time -l` 退出记录，先用触碰 32 MiB 的自有子进程校准单位，不读取系统进程列表。

固定 Pika：`bcc83f88ee18760e60903d1a3aaa61ef6f70f2c9`，二进制散列 `f32d3c6dfe4d6d90da7728d9cc2af68c3195a1cefb1bc28f3829f174c518dba1`。配置 Threads=4、Hash=64 MiB、MoveOverhead=0，该构建是 HCE，非 NNUE。Mist 暗局节点已合计八世界，不能再乘八。稳定版单世界实际一搜索线程，候选/Pika 上限四线程；上限相同不等于实际资源消耗完全相同。每手主机预算 2000 ms、主机预留 40 ms；Mist 内核还有最多 35 ms 预留，导致有效计算时长略短。旧无关构建终态仍未知，不能证明完全没有背景争用，交错顺序只能减轻影响。

规则仍有未完成工作：公共裁判 `cn2020-evidence-v1` 对已识别单方长将按责任判负，对复杂待判循环列为未决；长杀、联合捉等不宣称完整合规。内层搜索保留旧循环启发式，未完全接上外围责任判定。新调度不应被当成规则修复或默认切换依据。

## 冻结试赛

固定 12 局已全部完成：一组新正常初始布局四局，两个预选编辑少根残局各四局；每组对稳定版和 Pika 换色。逐手持久化、独立回放 340 半回合及 15 次暗俘观察检查通过；技术失败、非法走法、超预算判负均为 0，无 fallback。稳定版有 66 次预期的主机截止返回，均不超过总预算，不改记为技术失败。

| 分组 | 对手 | 胜 / 和 / 负 | 未决 | 已决得分率 |
|---|---|---|---:|---:|
| 正常初始布局 | 稳定版 | 0 / 0 / 2 | 0 | 0% |
| 正常初始布局 | 固定 Pika | 0 / 0 / 0 | 2 | 无已决局，不能计算 |
| 编辑少根残局 | 稳定版 | 2 / 0 / 2 | 0 | 50% |
| 编辑少根残局 | 固定 Pika | 2 / 0 / 2 | 0 | 50% |

正常布局对稳定版一局因候选红方单方长将被判负，另一局被将死。对 Pika 两局在112和47半回合进入需人工裁决的复杂循环，保留未决，不当和棋、不用评估值代判。合计对稳定版2胜4负（33.3%），对Pika2胜2负2未决（仅4已决局50%）；不能混同正常开局和编辑残局的意义。

四局正常开局候选共145手，没有触发新全明少根调度。八局编辑残局共24手候选走子，仅6手报告触发（分布在四局、累计10个展开父节点），其余走旧路径。两编辑局面实际均为黑方短线获胜，4或8半回合结束；换色50%主要反映初始局势，远不足证明棋力。候选没有主机强停，因此这些触发计数来自最终结果；若其他重放出现主机强停，缺少最终字段只能作触发下界。

准备阶段曾因重用输出文件名、已知全暗公开视图重复校验及整理脚本空捕获字段而停止，均在启动对应搜索前或离线整理时恢复，旧记录未覆盖；未把这些准备错误混入正式对局胜负。

本轮结论是已得到可复现的局部并行效率收益，仍有快速终局成本、首分支串行尾部、未充分覆盖的长残局和循环规则整合问题。保留可选原型，不切换生产默认。下一有依据的方向是首分支内的更细分裂/安全窃取，必须继续测额外工作和尾部，而不能仅追求四核满载。
