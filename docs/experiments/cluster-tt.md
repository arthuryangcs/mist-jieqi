# 固定内存置换表与对照条件校正（2026-10-30）

本轮没有证明净棋力收益，新表保持非默认。它对规范化稳定版2胜1和1负，对固定Pika1胜3负；稳定版对同一Pika为2胜2负。同局面2秒基准没有普遍加深。

本轮假设是：把每个采样世界的节点哈希表改为连续、两路组相联表，减少节点分配与指针访问，在同样时间内增加有效搜索。只改变置换表布局及替换策略，没有叠加LMR、明子静态将军或估值改动。默认仍是无人工主深度上限的HCE；实际走子深度、停止、重开与过期响应处理均保留。

## 版本与资源

原稳定源码SHA `3fa98d62f3c1636b831680fcd5dcbf88f9339e966ed1b8e2f8a170b83afcbfb0`，二进制SHA `7262d0abda78f09162c6e87045ac81d9c2b73ad8e445d277fbc8ced39926dbea`，原样保留。

本轮正式对照使用资源规范化的稳定HCE：原搜索、每世界9万项上限与已有键更新不变，预留桶并从请求共用的64MiB有界arena分配。它与原稳定版不是同一二进制。五类固定局面各35万节点的推荐、根表各项评分、完成迭代与节点数逐项相同；直接容量测试另覆盖填满9万项、已有键更新及分配失败。64MiB是arena负载分配上限，控制保留9万项约束，因此全明单世界通常实际仅用约7.2MB；试验分配完整64MiB。桶/节点容量及替换机会随表结构而变，不能把性能差异单独归因于指针访问。正式记录要求零分配拒绝，避免缓存静默降级后仍宣称控制组语义不变。构建记录为 `control-build.json`，源46f7e906、二进制494eb5b6。

试验表每项64字节、每桶两项，保留原完整Key（双32位局面哈希、行棋方、库存数量/总值与延伸预算），精确比较整个Key；没有把哈希碰撞的概率说成零。命中更新；空位优先；满桶仅以至少同等深度的新项替换较浅项。64MiB在各世界之间按2次幂分配，8世界各8MiB，全明1世界64MiB。表不跨观察者、请求或采样世界共享。源4faf7bd8、二进制f3798da8；完整SHA与编译器/参数见 `trial-build.json`。代码为本项目独立实现，没有复制外部引擎实现或网络。

固定Pika仍是 `brianhliou/pikafish-jieqi-wasm` 提交 `bcc83f88ee18760e60903d1a3aaa61ef6f70f2c9`，二进制SHA `f32d3c6dfe4d6d90da7728d9cc2af68c3195a1cefb1bc28f3829f174c518dba1`，原HCE构建 `USE_NNUEEVAL=0`，没有重编译、修改或加载新权重。来源许可和既有构建核验见 `benchmarks/requested-engine-build.json` 及第三方声明；第三方源码、可执行文件及权重不分发。

三方每手2000ms、最多4个搜索线程、TT预算64MiB；Mist仍8个合法观察样本、全明1样本/1线程，Pika使用自身既有概率搜索。初始化握手在每手外，投影、采样、协议校验、IPC、停止及清理在每手内，技术判负宽限60ms。HCE保留原内置最多35ms收尾预留，Pika的MoveOverhead为0；宿主总预算相同，有效核心计算时间并非精确相等。统一的是时间、线程上限和TT预算，并非整个进程RSS或相同并行算法；棋盘、栈、历史及其他状态仍不同。Mist每手按新观察种子重建样本和TT；固定Pika在同局进程内保留自身搜索状态，这也是算法差异，未为追求表面一致而逐手清空对手。原稳定二进制还单独参加同局面性能基准，避免把资源规范化的影响全部归因给新表。

## Pika颜色偏差的处理边界

此前六组可达局面的旋转换色直接eval不对称证据保留在 `benchmarks/native-symmetry.json`。本轮让固定Pika总是以自身为红方的坐标系接收局面：实际执黑时旋转180度并交换颜色，推荐再映回真实棋盘。这定义了新的“规范视角Pika参考”，不能与历史原始视角的胜率混合，也不等于证明或修好了上游内部估值问题。

适配同时变换起始FEN、走法白名单、整个6字符历史、揭子字符和仅吃子方可知的暗俘字符。起始在规范坐标为黑走时，对整步计数作对应偏移，使后续历史推移一致；不修改裁判的实际ply。30次历史/库存及整步计数、4次合法着集合、80次相反颜色镜像输入一致性、7项隐私检查通过。红黑各一次2秒搜索预检都返回原始观察局面的合法着。只接受过滤后的publicState，未知暗俘扰动不改变传输内容。

公开裁判仍为第三次同公开棋盘及行棋方出现，造成重复者判负，将死/困毙优先；120闲步和棋，400半回合未决。Pika根白名单排除立即重复判负的走法（若全都输则保留）。双方内部深层循环与闲步计数近似仍不同，报告不声称内部规则完全一致。

## 正确性与同局面性能

release与ASan/UBSan各通过24个观察视角、508次走子/撤销、20项隐私检查、197次样本分数聚合。红黑回归均保留R2/N1/A2/P3的8个分支以及深度2下6个立即将杀损失。碰撞专项涵盖8个Key字段、世界隔离、替换、满表、分配失败、正负将杀值随ply的归一化与上下界。10半回合回归证明没有恢复8层主搜上限。

原项目加适配回归共151项JavaScript测试、72个native规则观察/2172次转换/16个搜索对照、8项真实HTTP服务检查通过。另对全明局面给300万节点预算，原稳定及规范化控制均访问3000001节点、完成迭代7，30个根候选逐项相同、最大差0；控制表负载7200008字节、拒绝0，覆盖较长搜索下的容量边界。保留此前浏览器访问限制，没有把DOM或HTTP测试算成真实浏览器视觉验收。

五类局面按三种实现交替顺序各测两次2秒。试验与规范化控制的实际最深半回合分别为：开局13/13、中局2111/20为13/13、中局2111/44为14/14、中局2221/44为13/13、全明10子为16/16；全部两次一致。完整迭代分别同为4、5、5、5、7。深度包含静态搜索与将军延伸，概率身份展开不另算走子；最深路径不是整树等深。

两次平均NPS的试验/控制比约为1.001、0.992、0.989、0.945、1.057。全明残局约快5.7%，一类中局约慢5.5%，其余接近；没有普遍搜索加深。原稳定版部分硬截止只有最新遥测下界，不把该节点数当精确值。表容量更大也不等于棋力更高，正式对赛另行判断。原始逐次数据见 `benchmark.json`、`performance-summary.json`。

对Pika的8局仍有实际红方7胜、黑方1胜。规范化证明的是相反颜色镜像观察的引擎输入一致；它不能消除先行、布局、策略及小样本的颜色分布，也不能证明内部估值已经对称。本轮与旧原始视角参考保持分开。

926手HCE最终TT报告全部齐全，分配拒绝均为0；控制实际负载上限57600064字节，试验每手67108864字节。最长宿主耗时：控制1975.726ms、试验1976.627ms、Pika2012.797ms，均低于2060ms技术界限。Pika有156手内部闲步字段与裁判不同，棋盘/行棋方/库存及整步字段始终一致；公开裁判统一，但内部循环/闲步近似仍须保留限制。

整场不同局面的实际selDepth中位数控制15、试验14，Pika18；局面分布和引擎定义不同，不作为同树性能排名。试验在276半回合的已知判和根着上空转1196866轮，实际访问0节点、深度0；这是既有外循环终止问题，未在冻结TT实验中混入修复。统计将其单列，未把该轮数当走子深度。

同局面原稳定二进制10次中8次需宿主硬截止，而两种arena版本各0次；这说明收尾行为有改善，不能自动转化成棋力收益。原源码在run返回、状态析构后才flush最终输出，arena省去逐节点释放可能是原因之一，但本轮未做独立析构耗时剖析，不能将全部差异归因于此。

后续更值得单独测量的是“全根着×全部世界”全窗口搜索的预算分配、跨手可安全复用状态及概率分支的有界搜索；本轮不再叠加新策略。保留有效的公平性检查和失败实验依据，默认算法及用户棋局不变。
