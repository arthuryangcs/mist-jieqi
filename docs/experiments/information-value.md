# 已知明子奖励试验

这是用户要求的“尝试计分”版本，保留为独立核心。默认 `127.0.0.1:8766` 的 C++ 源码和二进制没有被替换。实验页使用 `127.0.0.1:8767`，搜索状态标为“已知明子+8实验”。没有开展长时间优化或对赛。

## 评分

在原估值上增加：`8 × (min(8,己方盘上明子数) − min(8,对方盘上明子数))`，将帅不计，离盘棋子不计，暗子采样真身不计。双方规则对称，差额范围为 −64～64 分，低于一枚兵的基础110分。将死/困毙及重复判负的终局评分不变。

这是“身份确定性”的粗略代理，不是经过证明的信息价值。原引擎已按真实子力、位置、身份池和未来走法计算收益，本项可能重复奖励揭子；平等增加明子数不一定带来真实优势。开局所有翻子都会得到小奖励，因此不能仅凭这个特征判断该翻马还是兵。

## 有限验证

- 7项策略断言：对称性、上限、将帅排除、暗子真身隔离、暗俘不重复计奖等。
- 8个固定局面，相同抽样和主深度：初始局面、红明黑暗上限场景、双向暗俘视角及4个既有短杀。非战术局面为1层，4个短杀为2层，采样为4（全明为1）。每次请求最多2秒。
- 298个走子后的评分与独立JS公式核对，包括撤销恢复。
- release与ASan/UBSan均通过；4个短杀仍找到既有已验证制胜着法。
- 8个局面中1个首选改变：固定种子6101、4样本的初始局面，原版从64走到1（暗炮纵向吃暗子），试验从64走到67（横移揭子）。两个不同评分函数的分数不可直接作为棋力比较。尚无证据说明这个变化更好，也不能证明不会诱导无意义揭子。

默认二进制前后哈希一致。本轮只做上述短验证，未更改默认权重、采样、深度或时间预算。历史实验、对赛分数不与本轮合并。

原始证据：[release](../../benchmarks/information-value/check.json)、[sanitizer](../../benchmarks/information-value/check-sanitized.json)。界面和服务验证见[自动同步检查](../../benchmarks/assistant-workspace/auto-sync-verification.json)，不等于真实浏览器渲染验证。
