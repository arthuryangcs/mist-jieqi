# 收尾时间预留实验

本轮保留为隔离实验，未启用为默认控制器。默认C++源码和二进制均未变化；没有叠加已知明子+8奖励、改估值、改采样或硬编码开局。

## 改动与工程验证

比较针对对赛控制器：原版组使用当前稳定搜索二进制和同一仪表控制器的0ms预留，不是浏览器HTTP/Worker服务的端到端基准。唯一试验差异是宿主将搜索截止提前40毫秒，为IPC解析、停止及进程退出/管道关闭留出空间。原控制器预留0毫秒，两者使用同一个当前稳定C++二进制。计时记录区分Node数据回调、JSON解析、计时器迟到、退出及管道关闭；数据回调时刻不是操作系统真实到达时刻。

既有历史超时曾超过1060ms；底层原因未确认。本轮故障注入只证明在所设延迟下的行为，不能追溯断言历史超时原因已修复。注入80ms收尾延迟时，0ms预留超过200+60ms测试宽限，40ms预留仍在宽限内；长宿主阻塞仍超时，不能宣称硬实时。

12次同预算基准（3局面×2轮×2版）如下，计入投影、准备、IPC、搜索、停止及回收；就绪在回合外。不同局面实战节点数不能拿来证明纯搜索加速。

| 局面 | 原版耗时中位数/完整层 | 40ms预留耗时中位数/完整层 |
|---|---|---|
| 初始全暗 | 993.1ms / 4 | 948.3ms / 4 |
| 可达中局 2111 / 20步 | 1001.1ms / 5 | 962.6ms / 5 |
| 全明10子残局 | 982.7ms / 6 | 941.2ms / 6 |

第一版验证错误地要求3万节点预算完成指定2层，实际仅完成1层；保留[首次失败记录](../../benchmarks/clock-validation/check-initial.json)，修正为如实核对已完成深度、候选与节点相等，没有增加预算来伪造完成层数。当前[检查](../../benchmarks/clock-validation/check.json)和[基准](../../benchmarks/clock-validation/benchmark.json)通过。

完整项目回归142项通过，见[单测记录](../../benchmarks/clock-validation/unit.json)。

## 新规则配对对局

两个预先冻结的新布局2026102101/2026102103，红黑换色。4局试验对当前稳定版，另8局原版/试验分别对固定Pika并轮换执行顺序。每手双方相同名义1000ms，共同60ms宽限，最多400步，搜索串行。原版和试验均8个无放回样本、全明1样本、最多4线程、每世界9万项TT、主深度上限8。就绪不计入回合，其余准备、FEN/根规则验证和回收均计入。其他应用和系统调度未受控制。

Pika仍为已授权HCE二进制 `bcc83f88` / `f32d3c6d…`，4线程、Hash64MiB、MoveOverhead0，本轮共同预留40ms；已知颜色估值不对称保持原样。外部适配器用标准UCI searchmoves，在有替代走法时排除直接触发第三次重复判负的根着，所有Pika组使用相同策略，没有修改第三方二进制。默认C++在根评分中已识别同一规则；双方深层循环仍各自近似，不能当作完整长将/长捉责任判定。

补充根规则验证使用9步合法循环，固定Pika实际排除了第三次重复判负根着，见[规则探针](../../benchmarks/clock-validation/rule-probe.json)。最初的全明无未知库存合成用例被固定比较器拒绝：对手FEN将空库存输出为空字段，适配器期望短横线。保留[失败记录](../../benchmarks/clock-validation/rule-probe-initial.json)，未修改冻结适配器或第三方，也未重跑正式对局；此格式边界仍是限制。

裁判统一使用当前规则：同一公开盘面及行棋方第三次出现，最后落子方判负；将死/困毙优先；120闲步和棋；400步封顶单列未决。没有混入历史重复判和结果，没有用估值提前认输。仅传行棋方publicState，暗俘身份只传给吃子方，初始真布局只由裁判持有。

## 限制与结论

独立回放核对690步、82次暗俘私人信息、2次重复判负、1次Pika根约束触发，全部通过。详见[原始对局](../../benchmarks/clock-validation/matches.json)及[回放验证](../../benchmarks/clock-validation/verification.json)。所有时间尝试含技术失败的p50/p95/最大值见[决策记录](../../benchmarks/clock-validation/decision.json)。

重复判负的逐局根走法诊断见决策JSON：若末步仅有一着合法且已出现两次，任何选择都直接判负。终局元数据可能显示8层、0节点，这不代表实际计算了8层，也不用于宣称深搜能力提升。

只有两个相关布局对，未完成既有8局筛选和独立20局确认门槛，因此无论本小样本得分如何，都不据此启用默认版本、宣称稳定棋力提升或推出Elo。减少计算时间可能损失层数；个别局面推荐变化不构成因果胜率证据。没有开展浏览器渲染验证，本轮没有UI或服务行为改动。

## 复现

使用新的输出目录或先显式保存现有证据，不覆盖冻结记录。固定对手路径由JIEQI_ENGINE_PATH提供；不下载或重编译第三方。

```sh
node native/experiments/coverage-validation/check.mjs
node native/experiments/coverage-validation/benchmark.mjs
node native/experiments/coverage-validation/matches.mjs freeze
node native/experiments/coverage-validation/matches.mjs next
node native/experiments/coverage-validation/verify.mjs
node native/experiments/coverage-validation/rule-probe.mjs
node native/experiments/coverage-validation/report.mjs
```

next每次只执行一局，有进程锁防止自身重叠；若需要停止，在`.cache/clock-validation/STOP`写入文件，当前一手结束后保存检查点并退出。恢复前确认额度和进程状态，再移除停止标志。主协议/源码哈希冻结后修改会拒绝续跑。
