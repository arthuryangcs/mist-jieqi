# 明子静态将军与晚着减层组合（2026-10-29）

本轮独立验证一个战术/预算组合：用晚着减层节省分支预算，支付每条静态搜索线路最多一次明子非吃子将军探测。它由两个已有机制组合，不能把成绩分别归因给任一单项。安静着查询提前过滤暗子与占用目标，只优化生成过程，不改变可探测走法。默认仍为无人工主深度上限的HCE，组合候选未默认启用。

## 来源与边界

稳定功能核心源SHA3fa98d62、二进制7262d0ab；候选源e16f1e53、二进制e2490bc6。候选从本项目源码生成，没有复制上游引擎实现或权重。上一轮LMR单项对AB0胜4负、内部2胜2负，不能据此直接启用；本轮重新使用指定固定PikaJieQi，不用AB替代。

Pika固定仓库brianhliou/pikafish-jieqi-wasm，提交`bcc83f88ee18760e60903d1a3aaa61ef6f70f2c9`，本机二进制SHA`f32d3c6dfe4d6d90da7728d9cc2af68c3195a1cefb1bc28f3829f174c518dba1`。仍为原HCE构建（USE_NNUEEVAL=0），未加载新NNUE；已知颜色估值不对称保持并披露，不据此挑选颜色。源码/二进制均不随本仓库分发。

双方每手2000ms、线程上限4；Pika Hash64MiB、MoveOverhead0；Mist8个合法观察者无放回样本、每世界9万项TT，全明1样本/1线程。不宣称进程RSS和评估开销完全相同。进程就绪在计时外；投影、采样、FEN及根重复核验、IPC、搜索、停止清理计入每手预算，技术宽限60ms。

公开裁判：第三次同公开棋盘与行棋方，造成重复者判负，将死/困毙优先；120不吃子半回合和棋，400半回合未决。Pika通过searchmoves排除立即重复判负的根着（全都会输时保留）；双方深层循环仍是各自近似，不能宣称内部规则完全一致，也不混入旧重复判和赛果。

## 回归与协议

release及ASAN/UBSAN均通过：24观察视角、506次走子撤销、14项隐私、197次根世界分数聚合检查；固定节点下trace/正式二进制候选完全一致，包含LMR触发及完整深度复查。10层稀疏局面回归确认无8层主搜上限。

已知回归局面中，红黑两色都保持R2/N1/A2/P3库存8分支，稳定版主搜第1层未发现6个分支的立即明子将杀，组合在第1层发现6/8。这个固定战术覆盖不等于总体棋力提升。

Pika适配只接受publicState前后观察，固定6字符协议，与AB可变后缀区分。移动暗子身份公开；暗俘后缀只给吃子方，从合法after视图读取，不从裁判暗子读取。30次历史FEN/库存、4组合合法着法、7项隐私扰动检查通过。首次预检曾因退出方法递归挂起，正式比赛前已清理、修复、重跑通过；这是预检故障，不混为正式对局失败，也不隐藏原本地日志。

另发现明确但未在本轮中途修改的效率问题：两个强制重复终局中，根着已经全部由规则确定，外层仍运行约193万/195万轮，访问节点0、实际半回合0。这些是规则直判的外层空转，**不是搜索到了百万步**；summary.json将其单列。保留冻结策略以免污染对照，后续可用精确规则快路径消除空转，无需把该数字包装为加深成果。

结论：组合补上了固定浅层将军回归，但同局面实际路径收益有限、正式对战未证明棋力提高，不默认启用，不声称超过Pika。样本仅2个布局、每组4局，颜色/布局影响和对手并行搜索波动显著，无法归因全部差距。默认仍为已验证的无主深度上限HCE。
