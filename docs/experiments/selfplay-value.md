# 新自对弈数据与小型残差评估：2026-11-08

本轮落实了“自己生成自对弈局面、再训练小网”的可复现闭环。不是下载人类棋谱、第三方数据或模型。所有生成、训练与正式赛程都预先固定；默认HCE与网页不变，用户已关闭的试玩版没有重启。

## 当前结论

一次120轮训练的验证集选中第1轮，测试损失略差于原HCE，没有泛化改善。第120轮训练损失下降而验证损失升高，说明继续拟合这批小数据不能当作有效优化。没有重训、扫参、选测试集或因输赢替换布局。

正式12局：候选对规范化HCE为2胜2负，两者对固定Pika均1胜3负，技术失败0。测试误差与对局均未证明收益；保持独立非默认实验，默认引擎不变。

## 先审计规则与信息

- 引擎只能收到该玩家合法可知的观察。盘上暗子真身、对方私有暗俘、未来走法、初始布局编号都不作特征或搜索随机数种子。
- 原`publicState`会透传额外顶层属性，因此本轮另加`lawfulView`白名单。裁判布局种子、真实布局、棋谱元数据始终放在状态外部；对改变不可见身份和额外真值字段做等价性测试。
- 数据抽取先逐手核对合法性、当前视角、采样种子、揭子与暗俘公开日志、校验和及终局，再赋标签。`move`本身不负责拒绝非法或终局后走子，生成器额外严格验证。
- 裁判：将死/困毙优先；同一公开盘面与行棋方第三次出现，最后走子方负；120闲步和；400步封顶未决。若同一步同时达到闲步和与封顶，按闲步和处理。技术失败和未决永不作为0.5和棋标签。
- 当前生产HCE内部仍将首次重复的采样搜索状态提前记0分；未携带完整裁判历史/quiet/ply。候选和规范化对照共同保留该近似，根着通过裁判元数据处理重复。本轮没有把它误写成完整重复/长将长捉规则，也没有把另一套search-speed核心混入模型对照。
- 神经特征包含分类型库存，候选TT/路径键因此显式包含完整库存。保留等总数、等总价值但士/象库存不同的回归，避免旧NNUE首版出现过的缓存依赖遗漏。

## 新数据：局面与完整对局分开统计

生成前固定[计划](../../native/experiments/selfplay-value/plan.json)。24个从未用于既有公开评测/旧NNUE数据的初始布局，每布局2个策略种子，共48局。采样种子由合法观察计算，策略随机数独立于真实布局。前8半回合从搜索完成的前三候选中随机选，之后走首选；没有故意随机丢子后重新挑选有利结果。

生成使用当前HCE，暗局8样本、全明1样本，主深度上限2层、30000节点上限，单线程逐手搜索并保留已完成的上一层。实测4018手完成2层、521手完成1层；1079手是全明1样本，不声称每手都完成8样本2层。10秒是安全超时而不是棋力赛预算；正式比赛另按每手2秒进行。不能把这48局说成高水平教师棋谱。

实际生成4539半回合：红胜27、黑胜19、120闲步和2、技术失败0、未决0。第8半回合起逐步抽取红黑各自合法视角，共8310条观察，其中奇数半回合4130条、偶数4180条。所有48局均符合样本条件。

## 一次训练与泛化结果

沿用本项目已有的2597维稀疏合法观察特征、16单元clipped ReLU、两个共享权重朝向累加器。红方HCE加一个±256分的反对称学习残差；float32权重、float64累加。自有随机初始化，41585参数、166364字节，不是Pikafish权重格式，也不是大型策略网络。

NumPy2.4.2 / Python3.14.3，本机CPU单次训练23.56秒，无安装、云训练、数据上传或网络权重下载。120个预定full-batch Adam epoch，seed1729、lr0.005、L2=0.0001，只按验证BCE选第1轮。测试文件独立保存；训练进程在写出float32模型和冻结记录后才首次读取测试文件。此前完整性/隐私审计会读取测试行，但不计算模型测试损失、不参与选模；后续独立数值重算也不参与选模。

## 实现与验证

生产源SHA256为`3fa98d62f3c1636b831680fcd5dcbf88f9339e966ed1b8e2f8a170b83afcbfb0`。仅构建独立control/candidate：两者均将原HCE的unordered_map置于同样64MiB硬预算arena，候选额外含网络和分类型库存键。规范化对照在5个固定局面的完整2层候选、分数和节点与生产HCE一致；这不是候选网络与HCE等价的声明。对照是**规范化稳定HCE**，不是声称原生产版原封不动具有64MiB硬上限。

release和ASan/UBSan分别通过：87个视角、2853次走子/撤销、1224次翻子、117次暗俘；增量/完整重建累加器最大差0，独立JS前向最大误差4.45e-16。10个搜索含串行/实际多线程、节点中断，逐层分数和节点一致。规则检查每版414组、11874次走子，覆盖马腿、象眼、炮架、明士象全盘、送将、困毙与暗俘库存等。

8组红黑/明暗/第二及第三重复根着检查通过；12次2000ms计时检查全部在共同2060ms上限内，三种代表局面的完整层数均为开局4、中局5、残局7，两臂相同。取消回收4.70ms，之后恢复搜索通过。全部项目测试165/165通过。生产原生检查另通过72组规则、2172次走子/撤销和16组搜索；HTTP流、旧客户端与取消8/8通过。

这是5轮轮换、每轮25000次调用，带no-inline和编译器屏障的微基准。增量比完整重建便宜，但比HCE单次评估多约31%–46%；未计入走子/撤销维护、较大缓存键及内存成本，不能据此算整体NPS或棋力。

## 来源、许可与交付范围

参考[jqe](https://github.com/devinokeefe/jieqi)的自对弈训练思路及[AB-JChess](https://github.com/lxsgx23/AB-JChess)的合法观察/库存约束。jqe主要自有代码与网络为MIT，其THIRD_PARTY还列明GPL例外；AB-JChess为GPLv3，当前main与本项目旧固定v0.2d不是同一架构时期。未复制上述代码、权重、转换模型或教师输出；没有把开源代码许可误当作未发布数据的下载授权。

jqe的默认按记录尾部验证切分不保证按布局隔离，封顶/应用失败记为结果0也不符合本轮标签语义，因此没有照搬。本轮自有代码与随机初始化训练出的权重随仓库GPLv3分发。全部第三方源码、可执行文件、网络权重及用户电脑信息留在公开仓库之外。

交付是可复现的小规模自对弈/训练/审计和独立候选，不是“已经超过Pika”。新数据量明显不足以支持扩大模型；若继续，应先增加真正独立布局、提高生成策略/标签质量，再预先固定新留出集，而非反复调这4个测试布局。暂不安排无限训练或默认切换。
