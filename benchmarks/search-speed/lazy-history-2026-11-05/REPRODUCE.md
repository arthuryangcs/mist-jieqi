# Reproduction and boundaries

This directory contains self-generated public views and synthetic games, not human game data. Referee hidden states and executable binaries are omitted. `manifest.json` hashes the curated files. Native node counts are already summed across eight sampled worlds. Pika node units differ.

## Portable checks and replay

Run from the repository root in an independent checkout. A local C++17 toolchain is needed for search checks. These commands never switch the production default:

```sh
node --test native/experiments/search-speed/lazy-history-source.test.mjs
node native/experiments/search-speed/check-lazy-history.mjs search
node native/experiments/search-speed/check-lazy-history.mjs rules
node native/experiments/search-speed/check-lazy-history.mjs reference
node native/experiments/search-speed/replay-lazy-history.mjs
```

Append `--sanitize` or `--tsan` to a check for the sanitizer build. The source checksum tests reproduce the exact optimized/unit source, both rejected derivatives and the instrumented setup source. Replay reconstructs the eight games and observer visibility without executing Pika. It rejects a changed referee source; use this recorded commit when replaying these games, rather than silently applying future rule changes.

## Actual performance setup

`performance-plan.json` freezes 15 views, all four binaries, 2000ms budgets, maximum four search threads, three rotations, and two new layouts/eight paired games. `fixtures.json`, `fixed-work.json`, `short-screen.json`, and `distribution.json` preserve every predetermined case, not only positive results. Short responses are compared by latency, not NPS. `validation.json` and `validation-rejected.json` distinguish the tested candidate from rejected variants and list sanitizer coverage.

Sources and versions:

- Candidate: generated by `lazy-history-source.mjs` and `build-lazy-history.mjs`; original uint32 HCE/history arithmetic, eight worlds, full roots.
- Incremental control: `deferred-order-source.mjs` and `build-deferred-order.mjs` from this repository.
- Stable control: main commit `fe810c7a265c6e5e2f0b3b2e51d283959d2f71a9`, `native/search.cpp` SHA256 `3fa98d62f3c1636b831680fcd5dcbf88f9339e966ed1b8e2f8a170b83afcbfb0`. Build it in a separate checkout; building this branch's modified repetition core is not the same stable control.
- Fixed Pika: upstream `brianhliou/pikafish-jieqi-wasm` commit `bcc83f88ee18760e60903d1a3aaa61ef6f70f2c9`, actual Mac executable SHA256 `f32d3c6dfe4d6d90da7728d9cc2af68c3195a1cefb1bc28f3829f174c518dba1`, HCE/NNUE disabled, Threads4/Hash64MiB/MoveOverhead0. No third-party executable is included here.

The actual self-authored orchestration scripts are retained under `scripts/`. They were run from `.cache/lazy-history-20261105/`, using the root checkout's historical bridge for timing and the separately source-hashed `cn2020-evidence-v1` worktree for adjudication. They require the guard service on `127.0.0.1:8766` with the unchanged stable source and stop their own work when it becomes busy. They refuse to overwrite result files and frozen game locks. Preserve old paused experiments.

A byte-identical timing rerun requires the recorded Mac binaries and bridge/referee versions. On another toolchain, build the fixed source and create a **new** experiment plan/adapter that records its actual executable hashes; do not rewrite old guards or claim it is the same run. Copy the recorded views when comparing work, rather than regenerating them through a changed public-state schema. The live scripts are archival reproduction evidence, not a portable one-command tournament installer. Only run third-party engines in an environment where their execution is authorized.

## CPU and rules

`cpu-requests.json` contains six ready controls and eighteen search requests. `scripts/cpu.py` validates descendant CPU accounting and uses only `getrusage(RUSAGE_CHILDREN)` for its own waited Node/engine subtree; no system process listing or attach. `cpu-summary.json` subtracts each engine's median ready CPU. Startup, shutdown and controller costs remain, so small values above four core-equivalents are not extra search threads.

`matches.json` contains every game, per-move elapsed time, raw reported metrics, revealed identity, public FEN, private-capture masking tokens and final result. `cycle-evidence.json` reconstructs public check evidence in the two losing unilateral-check games. `zero-node-diagnostic.json` flags the unchanged stable engine's zero-node empty-iteration counter; its million-level iteration count is not actual ply depth. Original rows remain untouched.

The common referee has `completeCompetitionRules:false`. Unsupported complex kill/chase or responsibility cases would be unresolved. Legacy internal search cycle estimates/root metadata remain approximate. This is a diagnostic tournament with that limitation, not proof of complete competition-rule equivalence. Do not mix its results with older last-mover-repeat-loss tournaments.
